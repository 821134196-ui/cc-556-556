# 家政钟点工服务时长与迟到结算系统

客户预约钟点工后，双方通过实际服务记录确认费用；出现迟到、加时、提前结束或完成情况争议时，
客服依据双方留痕处理。后端 Java + Quarkus + Hibernate ORM + SQLite，前端 Svelte 5 + Vite，
定位与支付回执全部本地模拟，**一条命令启动**：

```bash
./run.sh
```

脚本会在没有 JDK 17 / Maven 时自动下载便携版到 `~/.housekeep-tools`，构建前端并打包运行。
启动后访问 **http://localhost:8080**（页面与 `/api` 接口由同一个进程提供）。
删除 `data/housekeep.db` 可重置全部演示数据。

## 角色与权限

左侧栏可切换身份模拟登录：

| 角色 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 客户 | 下单、确认到达/离开时间、确认任务完成、发起争议、确认结算扣款 | 不能替服务员打卡 |
| 服务员 | 上报到达/离开、中途外出/返回；**只能看自己的订单** | 不能确认完成、不能看他人订单 |
| 客服 | 查看全部订单、处理挂起争议（采信一方记录） | **不能代客户确认完成、不能直接改计时** |

服务记录（到达/离开/外出/返回）**只能追加，不可修改或删除**。
中途外出、客户拒签或双方对完成情况有异议时，争议金额立即挂起冻结，
双方都无法继续改计时或结算，只能由客服依据双方记录处理。

## 计费规则（订单页面完整展示每一条费用变化）

- 约定服务费：约定时长不足 1 小时按 1 小时向上取整 × 小时单价；
- **迟到**：宽限 5 分钟；超出部分按分钟单价（时薪/60）从约定费扣减，扣完为止；
- **临时加活（加时）**：实际工作时长超过约定时长，超出部分按 30 分钟一档向上取整加收；
- **提前结束**：比约定少做超过 10 分钟，按实际时长重新计费（不足 1 小时按 1 小时）；
- **中途外出**：`外出 → 返回` 区间暂停，不计入服务时长；
- **跨日服务**：所有时间按 Asia/Shanghai 解释，存 epoch 绝对时间，页面标注跨日与自然日数。

## 演示场景（启动后自带数据）

1. **跨日计时**：订单 #1，2026-10-08 22:00 开工，含 30 分钟中途外出，次日 02:40 才离开
   （客户临时加擦两扇落地窗）。实际工作 250 分钟，跨 2 个自然日，约定 200.00 元 + 加时 25.00 元 = **225.00 元**。
2. **双方确认冲突**：订单 #3，服务员主张 17:00 离开（240 分钟，含 60 分钟加时费），
   客户主张 16:00 离开（180 分钟无加时）。双方离开记录一到齐，系统**自动挂起争议**并冻结金额；
   客服在订单页可并排看到两种口径的账单，只能选择采信一方，不能改打卡时间。
3. **退款接口重复回传**：订单 #4（客户拒签油烟机清洁，客服采信客户 90 分钟主张后已扣款）。
   在订单页用同一个“回执幂等键”连续点两次“回传退款回执”：第二次提示幂等拦截，
   累计退款始终是 100.00 元，不会多退；再换新键退超出余额的金额会被拒绝（409）。
4. 另含：订单 #2 迟到 20 分钟（扣 12.50 元）；订单 #5 为空白预约，可手动走完整流程。

也可用脚本一键验证上述场景与权限规则：

```bash
node scripts/verify.mjs            # 需先 ./run.sh 启动服务
```

## 幂等与一致性

- `payments.idempotencyKey` 数据库唯一约束 + 业务查重双重保障：
  - 结算确认重复提交 → 直接回传原扣款流水，**不二次扣款**；
  - 退款/扣款回执重复回传 → 只入账一次，**退款绝不多退**；
  - 退款金额还会校验“累计扣款 − 累计退款”的可退余额，超额拒绝。
- 争议挂起状态下，计时与结算接口一律返回 409；客服处理后订单回到挂起前流程节点，
  完成确认仍必须由客户本人操作。

## 接口一览（`/api`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/users` | 用户列表（切换演示身份） |
| POST | `/orders` | 客户下单 |
| GET | `/orders?viewerId=&viewerRole=` | 按角色过滤订单（服务员仅自己的） |
| GET | `/orders/{id}?viewerId=&viewerRole=` | 订单详情：记录、争议、流水、费用拆解、双方口径、冲突点 |
| POST | `/orders/{id}/clock` | 到达/离开/外出/返回记录（服务员上报、客户确认） |
| POST | `/orders/{id}/confirm-completion` | 仅客户本人确认完成 |
| POST | `/orders/{id}/disputes` | 客户/服务员发起争议（挂起金额） |
| POST | `/orders/{id}/resolve` | 仅客服处理争议（APPROVED 服务员 / DENY 客户主张） |
| POST | `/orders/{id}/settle` | 客户确认结算扣款（幂等） |
| POST | `/orders/{id}/payments/callback` | 模拟支付/退款回执（幂等，防多退） |

## 技术结构

```
pom.xml                         Quarkus 3.15（Java 17）
src/main/java/com/example/hk/
  model/                        Order / WorkEvent / Dispute / Payment / User 实体（Hibernate）
  service/                      BillingService（计费引擎）、OrderService（事务与权限）、
                                MockPaymentGateway（本地模拟支付）、TimeUtil（跨日/时区）
  web/                          REST 资源、DTO 组装、异常映射
  bootstrap/DataInitializer     五个演示订单
frontend/                       Svelte 5 + Vite（构建产物直接打进 Quarkus 静态资源）
scripts/verify.mjs              端到端场景与权限验证
run.sh                          一条命令：备工具 → 构建前后端 → 启动
data/housekeep.db               SQLite 数据库文件（首次启动自动建表并填充演示数据）
```
